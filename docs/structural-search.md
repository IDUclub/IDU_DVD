# Поиск по структуре и наименованию фрагмента

Структурный адрес не является семантическим запросом. Например, пункт `3.3`
может иметь тип `definition`: ограничение `types=["clause"]` исключит его.
Поиск ниже сравнивает адреса и наименования независимо от типа документа.

## REST и MCP

REST: `POST /search/structure`, `POST /search/names`.
MCP: `search_structure(request={...})`, `search_fragment_names(request={...})`.
У первого MCP-инструмента обязателен `pattern`, у второго — `name_query`.
REST допускает любой из селекторов; при совместном указании действует AND.

```json
{
  "document_names": ["СП 2.13130.2020"],
  "version": "2020",
  "pattern": "3.3",
  "include_children": true,
  "limit": 100
}
```

| Параметр | Значение |
|---|---|
| `pattern` | Точный адрес `3.3`, маска `3.*`, диапазон `3.3–3.5`, путь `А / 2` или `Пожарная безопасность / 3.3` |
| `name_query` | Собственное наименование фрагмента, а не название документа |
| `name_mode` | `strict`: нормализованное совпадение, подстрока, маска; `expanded`: дополнительно близкие словоформы/опечатки и семантика наименований |
| `name_scope` | `self`: собственное имя; `path`: собственное имя или имя предка |
| `include_children` | По умолчанию `true`; все доступные потомки найденных корней |
| `doc_id`, `document_names`, `version` | Ограничения документа и редакции; автоматически не снимаются |
| `limit`, `cursor` | Размер страницы 1–200 и непрозрачный курсор следующей страницы |

`3.3` не совпадает с `3.30`. `3.*` охватывает `3.1.2`, но не `30.1`.
Диапазон включителен, его границы должны иметь общего родителя и числовую
последнюю компоненту. Компоненты пути задают предков в указанном порядке.
Это ограниченный язык масок, произвольные регулярные выражения не исполняются.
Регистр, пробелы и `ё/е` нормализуются. Для обозначения документа дополнительно
игнорируются разделители и повторённый конечный год: `СП2.13130.2020 2020`.

Ответ содержит `hits`, `total`, `match_count`, `complete`, `next_cursor`.
`matched=true` означает найденный корень, `false` — его потомка.
`match_kind` объясняет совпадение: structure/exact/contains/mask/fuzzy/semantic/descendant.
Лексические совпадения наименований располагаются выше семантических.
Внутри группы сохраняется порядок документа, фрагменты не дублируются.

Если `complete=false`, повторяйте **тот же запрос** с `next_cursor` до завершения.
Изменение документов или набора результатов делает курсор недействительным:
нужно начать заново, а не смешивать страницы. `ambiguous=true` и `candidates`
позволяют уточнить документ, редакцию или путь. При `candidates_complete=false`
показаны только первые 200 кандидатов; это не полный перечень.

Авторизация и область project/scenario совпадают с обычным поиском. Пользователь
не может подменить `user_id`. Потомки и предки не выходят за доступную область
и заданную редакцию. Ограничения по территории/блоку также сохраняются.

## Наименования и обновление старой базы

Каждый новый фрагмент получает `fragment_name` (или `null`), нормализованный
`fragment_name_key`, `fragment_name_path`, `structure_path`, `ancestor_ids`,
`fragment_name_source` и `fragment_name_schema=1`. Название всего документа
остаётся в поле `name`. Наименование фрагмента берётся только из его исходного
текста: заголовок, определяемый термин, подпись. Придуманные моделью описания
не принимаются. Родительское название не записывается как собственное.

При загрузке модель предлагает исходный фрагмент названия; дополнительно работают
правила извлечения явных заголовков и терминов. При чтении старых данных те же
правила работают без переиндексации векторов. Они не распознают гарантированно
все произвольные способы оформления: нераспознанное имя остаётся `null`.

Администратор может сохранить вычисленные поля:

```http
POST /library/fragment-names/backfill
Authorization: Bearer <admin-token>
Content-Type: application/json

{"doc_id":"<document-id>","dry_run":true,"limit":200}
```

1. Пройти все страницы предпросмотра, каждый раз передавая `next_cursor`.
2. Проверить `changes`, `without_name`, `would_update`.
3. Начать применение с **первой страницы**, `cursor=null`, `dry_run=false`.
4. Сохранять возвращённый курсор после успешной страницы; продолжать до `complete=true`.

Без `user_id` обновляется только общая база. Для частного индекса администратор
должен явно передать **оба** `user_id` и `project_id`; область не расширяется.
Операция идемпотентна, меняет только поля наименований/путей, не текст и не векторы.
После изменения исходного текста во время обработки нужен новый предпросмотр.

Полный текстовый скан ограничен 50 000 фрагментами выбранной области; превышение
возвращает ошибку с просьбой сузить область. Обозначения документов ищутся отдельно
потоковым чтением только идентификационных полей, поэтому размер остального корпуса
не расходует этот лимит. Expanded-поиск ограничен 5 000 различными наименованиями
и требует сервиса embeddings. Сейчас их векторы вычисляются на запрос; для большой
нагрузки потребуется отдельный индекс/кэш наименований. Ограничения никогда не
превращаются в молчаливую выдачу первых N результатов.

## Ввод в эксплуатацию

`context_height` применяется и к структурному поиску, и к поиску наименований:
в `hit.context` добавляются соседние фрагменты по `prev_id`/`next_id`. Это сохраняет
продолжение предложения, если ссылка или таблица попала в следующий фрагмент.
При нулевой высоте `context=null`; число соседей ограничено `max_context_height`.
Набор совпадений, `total` и пагинация не расширяются. Соседи берутся только из
уже отфильтрованного снимка с сохранением документа и области доступа; циклы и
ссылки за пределы снимка останавливают обход. Изменение соседских ссылок делает
старый курсор недействительным. Переиндексация не требуется.

Сначала развернуть IDU_DVD с новыми MCP-инструментами, затем gMART. Проверить
точный запрос выше: возвращается определение 3.3 с потомками, без фильтра типа.
Выполнить предпросмотр и применение наименований по документам. Продакшен-данные
не обновляются автоматически при старте приложения.
