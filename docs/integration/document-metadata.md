# Изменение территории и версии документа

Инструкция для интеграции с API метаданных пользовательских документов DVD.
Территорию и обозначение существующей версии можно менять отдельно или одним запросом,
без повторной загрузки файла и переиндексации. Текст, исходный файл и эмбеддинги сохраняются.

## Адрес и авторизация

```http
PATCH /user-documents/{doc_id}/metadata?project_id={project_id}
Authorization: Bearer TOKEN
Content-Type: application/json
```

| Параметр | Где передаётся | Значение |
| --- | --- | --- |
| `doc_id` | Путь | ID документа, полученный из списка документов. Это не название и не ID задачи загрузки. |
| `project_id` | Query | Обязательный ID проекта, которому принадлежит документ. |
| `Authorization` | Заголовок | `Bearer` и действующий токен Keycloak. |
| `X-User-Id` | Заголовок | ID владельца документа; обязателен при использовании сервисного токена. |

При пользовательском токене владелец определяется по `sub` токена; `X-User-Id` игнорируется.
При сервисном токене владелец берётся из `X-User-Id`. Пара `(владелец, project_id)` задаёт область
доступа: документ другого пользователя или проекта возвращает `404`.

Далее `http://localhost:8000` — пример базового адреса. Для интеграции замените его адресом
своего экземпляра DVD, а `TOKEN`, `PROJECT_ID` и `DOC_ID` — реальными значениями.

## Получение документа и текущих версий

Получите компактный список полностью проиндексированных документов проекта:

```http
GET /user-documents/available?project_id=PROJECT_ID
Authorization: Bearer TOKEN
```

В элементах массива `documents` доступны `doc_id`, `name`, `version`, `territory_id` и
`territory_name`. Для выбора версии также можно использовать полный список:

```http
GET /user-documents?project_id=PROJECT_ID
Authorization: Bearer TOKEN
```

Он содержит записи по `(name, version)`. Выберите запись нужной редакции и используйте её
`doc_id` и `version` в запросе обновления. У нескольких редакций может быть общий `doc_id`.

```bash
curl "http://localhost:8000/user-documents?project_id=PROJECT_ID" -H "Authorization: Bearer TOKEN"
```

При сервисном токене добавляйте `-H "X-User-Id: USER_ID"` ко всем запросам, включая чтение.

## Поля запроса

| Поле JSON | Тип | Правила |
| --- | --- | --- |
| `territory_id` | Целое число или `null` | Один ID территории из Urban API. `null` снимает привязку. |
| `version` | Непустая строка | Новое обозначение существующей редакции. `null` и пустая строка запрещены. |
| `current_version` | Непустая строка | Текущее обозначение переименовываемой редакции. Обязательно, если у `doc_id` несколько версий. Передаётся только вместе с `version`. |

Поля передаются на верхнем уровне JSON, а не внутри объекта `metadata`.
Пропущенные поля не изменяются. Передайте хотя бы одно изменяемое поле; пустой объект возвращает `422`.

## Изменение территории

```json
{
  "territory_id": 54
}
```

`54` — пример ID, а не код региона или название территории. Используйте существующий ID
из Urban API. Уровень территории, название и цепочка предков определяются автоматически.

Привязка записывается во все фрагменты указанного `doc_id`, включая общие фрагменты нескольких
редакций. Она помечается как ручная, поэтому автоматическое определение её не перезаписывает.
`current_version` не ограничивает действие территории одной редакцией.

Чтобы снять привязку:

```json
{
  "territory_id": null
}
```

Документ возвращается в состояние ожидания автоматического определения территории.
Сам запрос сброса не гарантирует немедленное определение новой территории.

## Изменение версии

Если у документа одна редакция, достаточно нового обозначения:

```json
{
  "version": "2026.2"
}
```

Если редакций несколько, явно укажите исходную:

```json
{
  "current_version": "2024",
  "version": "Редакция от 08.09.2026"
}
```

Можно переименовать любую сохранённую редакцию указанного `doc_id`, в том числе старую.
Обозначение не обязано быть годом или номером: допускается любая непустая строка.
Пробелы по краям `version` и `current_version` удаляются.

Операция меняет обозначение редакции, сохраняя её содержимое, исходный файл, `doc_id` и `version_id`.
Другие редакции сохраняются; общие фрагменты продолжают принадлежать каждой из своих версий.
Для явного выбора редакции при поиске и скачивании после обновления используйте новое обозначение.

Новое обозначение должно быть свободным среди версий документа с тем же `name` в текущем проекте
и у текущего владельца. Если уже существуют `2024` и `2025`, запрос `2024 → 2025` вернёт `422`.
Перезапись или объединение двух существующих редакций этим методом не поддерживаются.
Указание того же обозначения, которое уже есть у выбранной редакции, разрешено.

## Территория и версия одним запросом

```http
PATCH /user-documents/DOC_ID/metadata?project_id=PROJECT_ID
Authorization: Bearer TOKEN
Content-Type: application/json

{
  "territory_id": 54,
  "current_version": "2026",
  "version": "2026.2"
}
```

Для воспроизводимого вызова сохраните JSON в `payload.json` в UTF-8:

```json
{
  "territory_id": 54,
  "current_version": "2026",
  "version": "2026.2"
}
```

Выполните:

```bash
curl -X PATCH "http://localhost:8000/user-documents/DOC_ID/metadata?project_id=PROJECT_ID" -H "Authorization: Bearer TOKEN" -H "Content-Type: application/json" --data-binary "@payload.json"
```

В Windows PowerShell используйте `curl.exe` вместо `curl`. Передача JSON через файл позволяет
сохранить кириллицу и избежать различий в экранировании кавычек между оболочками.

## Успешный ответ и проверка результата

Метод возвращает `200 OK` с результатом выполненного обновления. Фоновая задача не создаётся,
`job_id` не возвращается; ожидать статус индексации не требуется.

Пример ответа при переименовании единственной версии документа с двумя фрагментами:

```json
{
  "doc_id": "DOC_ID",
  "points_updated": 2,
  "fields_updated": ["version", "versions"]
}
```

| Поле | Значение |
| --- | --- |
| `doc_id` | ID документа из запроса. |
| `points_updated` | Число затронутых фрагментов. При переименовании учитывает также фрагменты соседних редакций, у которых изменился список `other_versions`. |
| `fields_updated` | Список обновлённых полей. Может включать вычисляемые поля территории и `versions`/`other_versions`, даже если их не было в запросе. |

После успешного ответа перечитайте список документов проекта. Для проверки версии можно указать
фильтр `GET /user-documents?project_id=PROJECT_ID&version=2026.2`.

Скачать исходный файл выбранной редакции можно через
`GET /user-documents/{name}/source?project_id=PROJECT_ID&version=2026.2`.
Здесь в пути используется `name`, а не `doc_id`. Кодируйте название и строку версии для URL
или используйте `source_file_url` из обновлённого списка документов.

## Ошибки

| HTTP | Причина |
| --- | --- |
| `401` | Недействительный или просроченный токен; отсутствует требуемый `X-User-Id` при сервисном токене. |
| `404` | Документ не найден в указанном проекте у текущего владельца; `current_version` не принадлежит документу; территория не найдена в Urban API. |
| `422` | Нет `project_id`; неверный тип поля; пустой запрос; пустая или `null`-версия; занято новое обозначение; не выбрана исходная версия при нескольких редакциях; передан `current_version` без `version`. |
| `502` | Urban API недоступен при разрешении территории. |

Пример ошибки совпадения с существующей версией:

```json
{
  "detail": "version already exists: 2025"
}
```

У ошибок валидации запроса `detail` может быть массивом описаний ошибок.
Проверки версии и разрешение территории выполняются до записи изменений: ошибка этих проверок
не применяет другие поля того же запроса.

## Когда нужен другой метод

| Задача | Метод |
| --- | --- |
| Исправить территорию или обозначение существующей редакции | `PATCH /user-documents/{doc_id}/metadata?project_id=...`, JSON из этой инструкции. |
| Загрузить новое содержимое как новую редакцию с сохранением прежних | `PATCH /user-documents/{name}?project_id=...`, multipart-поля `file` и `version`. |
| Полностью заменить документ, удалив все прежние редакции | `PUT /user-documents/{name}?project_id=...`, multipart-поля `file` и `version`. |

Загрузка содержимого через `PATCH` или `PUT` возвращает `202` с `job_id`;
статус обработки доступен через `GET /user-documents/jobs/{job_id}`.
Полный дубликат содержимого при `PATCH` отклоняется с `400`; для исправления обозначения версии
того же файла используйте JSON-метод метаданных.

## Общие документы

Административный `PATCH /library/documents/{doc_id}` принимает те же поля `territory_id`,
`current_version` и `version` с теми же правилами переименования. `project_id` ему не нужен.
Для изменения общих документов требуется пользовательский токен с административной ролью
или сервисный токен. Для документов пользователя применяйте `/user-documents/...`.
