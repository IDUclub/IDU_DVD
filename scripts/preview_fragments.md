# Просмотр итоговых фрагментов

Из корня репозитория, с установленными зависимостями (`uv sync`):

```bash
uv run python scripts/preview_fragments.py /path/to/document.docx
uv run python scripts/preview_fragments.py /path/to/document.docx --output-dir /tmp/document-preview
```

Поддерживаются `.docx`, `.txt`, `.md`, `.html`, `.htm`. Скрипт читает обычные
настройки приложения из `.env` и переменных `DVD_*`, включая провайдера/модель LLM
и `DVD_LOGICAL_PARTITION_MODE`. Сервер API запускать не нужно. Обязательные поля
service auth заполняются локальными заглушками внутри процесса, если не заданы в
окружении: авторизация в этом скрипте не используется. Нужен доступ к настроенному LLM: обработка большого
документа занимает столько же времени, сколько соответствующие этапы загрузки.

Результаты по умолчанию сохраняются в `_uploads/preview/<имя файла>/`:

- `fragments.txt` — все фрагменты в порядке чтения, без обрезки текста; отдельно
  показаны текст для векторизации, исходный текст и HTML таблиц.
- `fragments.json` — структура, номера, теги, родители/дети/соседи, исходные
  диапазоны, `text`, `search_text`, `source_text` и фактический `embedding_text`.

Включены также узлы-контейнеры, которые штатный `ingest` передаёт в Qdrant.
Повторный запуск перезаписывает отчёты в выбранной папке.

Это предпросмотр **содержимого и структуры**, а не полный Qdrant payload:
скрипт не вычисляет векторы, идентичность/версию документа, административную
территорию и междокументные ссылки. Qdrant, Redis, MinIO и Kafka не используются.
UUID в отчётах временные. Последующая загрузка заново вызывает LLM и может дать
другую нарезку; отчёт не фиксирует результат будущего запуска.
